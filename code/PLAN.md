# RentUA – план реалізації

Вебзастосунок для довгострокової оренди житла в містах України. Стек: Next.js (App Router), TypeScript (strict), Tailwind CSS, shadcn/ui, Firebase (Auth + Firestore). Основа роботи – власні структури даних: **B-дерево**, **Trie**, **хеш-таблиця**. Усі пошуки, фільтри й сортування виконуються над ними в пам'яті клієнта.

## 1. Прийняті рішення

- Firestore – єдине джерело істини й сховище. Оголошення завантажуються в пам'ять одразу при старті застосунку (без входу), заявки й вподобання – після входу. Далі все синхронізується слухачами `onSnapshot`. Пошук, фільтри й сортування на Firestore-запитах не будуються.
- Перегляд і пошук оголошень доступні без автентифікації. Для вподобань, заявок і керування оголошеннями потрібен вхід.
- Індекси змінюються **лише** з обробника снепшотів. Сервіси пишуть тільки у Firestore.
- Наслідування не використовується (жодного `extends`). Зв'язки між класами – композиція та залежності через конструктор.
- Репозиторії працюють зі структурами даних напряму, без проміжних обгорток.
- Observer зведений до одного місця: `FirestoreSyncService` сповіщає React про зміни даних.
- Автентифікація: Firebase Auth (логін + пароль) і колекція `users` для профілю.
- Ціна – грн/міс, площа – м².
- Поле «Країна» – текстове, з підказками з Trie.
- Тести не пишемо, перевірка вручну за сценаріями з розділу 12.
- Застосунок лежить прямо в `code/` (там `package.json`).
- Інтерфейс українською, ідентифікатори й назви файлів англійською, коментарі українською й стислі.

## 2. Ролі та сценарії

Один акаунт може бути і орендодавцем, і орендарем. Роль визначається контекстом: власник оголошення – орендодавець, інші – орендарі. Подати заявку на власне оголошення не можна.

**Гість (без входу)**

- Перегляд каталогу й сторінки оголошення, пошук за адресою, фільтри, діапазон ціни, сортування.
- Будь-яка дія, що потребує акаунта (вподобання, заявка, сторінки орендаря й орендодавця), переспрямовує на вхід, після якого користувач повертається на попередню сторінку.

**Орендар**

- Каталог: пошук за адресою, фільтр за кімнатами, діапазон ціни, сортування за датою, площею, ціною.
- Вподобання оголошень і окрема сторінка збережених.
- Подання заявки, перегляд своїх заявок за станами, скасування заявки в стані «Очікує».

**Орендодавець**

- Створення, редагування, поновлення, скасування (повне видалення) оголошення.
- Перегляд заявок на своє оголошення, схвалення або відхилення.

## 3. Модель даних

### 3.1. Сутності

**Address** (value object): `country`, `city`, `street`, `building`, `apartment` – рядки, усі обов'язкові.

- `format()` – `Україна, місто Запоріжжя, вулиця Полякова, буд. 21, кв. 71`.
- `toTriePath()` – нормалізований ключ (нижній регістр, обрізані пробіли, без приставок), рівні розділені символом `\u001F`: `україна␟запоріжжя␟полякова␟21␟71`.

**Listing**

| Поле | Тип | Примітка |
|---|---|---|
| id | string | автоідентифікатор Firestore |
| ownerId | string | `uid` власника |
| ownerName, ownerPhone | string | вводяться у формі, ім'я за замовчуванням з профілю |
| address | Address | |
| rooms | number | ціле, 1–10 |
| area | number | м², 5–1000 |
| description | string | до 2000 символів |
| pricePerMonth | number | ціле, грн/міс |
| status | `OPEN` / `CLOSED` | |
| approvedApplicationId | string / null | |
| createdAt, updatedAt | number | мс |

**Application**

| Поле | Тип | Примітка |
|---|---|---|
| id, listingId | string | |
| ownerId | string | денормалізовано для запитів і правил |
| applicantId | string | |
| applicantName, contact | string | |
| comment | string / null | необов'язковий |
| status | `PENDING`, `APPROVED`, `REJECTED`, `CANCELLED`, `REVOKED` | |
| createdAt, updatedAt | number | |

**Favorite**: `id` (`${userId}_${listingId}`), `userId`, `listingId`, `createdAt`.

**UserProfile**: `uid`, `login`, `firstName`, `lastName`, `createdAt`.

Сутності імутабельні: методи станів повертають нову копію й кидають `DomainError` при неприпустимому переході. Значення полів сутності не перевіряють: це робить форма (розділ 8).

### 3.2. Стани й переходи

Позначення станів у UI: «Очікує», «Схвалена», «Відхилена», «Скасована», «Анульована»; оголошення – «Здається» / «Закрито».

| Дія | Хто | Умова | Результат |
|---|---|---|---|
| Створення оголошення | автор | – | `OPEN` |
| Редагування | власник | `OPEN` | поля оновлені |
| Подання заявки | не власник | оголошення `OPEN`, у користувача немає `PENDING`-заявки на нього | `PENDING` |
| Скасування заявки | автор | `PENDING` | `CANCELLED` |
| Відхилення заявки | власник | `PENDING` | `REJECTED` |
| Схвалення заявки (закриття) | власник | оголошення `OPEN`, заявка `PENDING` | оголошення `CLOSED`, заявка `APPROVED`, решта `PENDING` – `REJECTED` |
| Поновлення | власник | `CLOSED` | оголошення `OPEN`, схвалена заявка – `REVOKED` |
| Скасування оголошення | власник | будь-який стан | видаляються оголошення, його заявки, вподобання на нього |

## 4. Firebase

### 4.1. Колекції

- `users/{uid}` – профіль.
- `listings/{id}`
- `applications/{id}`
- `favorites/{userId_listingId}`

Усі запити – з рівністю по одному полю, тому складені індекси Firestore не потрібні. Метки часу зберігаємо як числа (мс).

### 4.2. Автентифікація

- Логін перетворюється на службовий email: `${login}@rentua.app`.
- Логін: `^[a-z0-9._-]{3,20}$`, нормалізується до нижнього регістру.
- Реєстрація: логін, ім'я, прізвище, пароль (мін. 6 символів), підтвердження пароля. Підтвердження перевіряється на клієнті.
- Після `createUserWithEmailAndPassword` пишемо `users/{uid}`. Якщо запис не вдався, видаляємо щойно створений акаунт Auth.
- Вхід: `signInWithEmailAndPassword`, далі читаємо `users/{uid}`, потім запускаємо синхронізацію користувацьких даних (заявки, вподобання).
- Помилки Auth перекладаємо українською (логін зайнятий, неправильний логін або пароль, занадто простий пароль).
- Відновлення пароля не передбачене.

### 4.3. Правила безпеки (`firestore.rules`)

- `listings`: читання відкрите для всіх, зокрема неавторизованих. Усі інші колекції та всі записи – лише для авторизованих.
- `users`: читати й писати лише власний документ.
- `listings`:
  - читають усі (`allow read: if true`);
  - створює автор (`ownerId == uid`, `status == OPEN`);
  - змінює й видаляє лише власник, `ownerId` незмінний.
- `applications`:
  - читає автор заявки або власник оголошення;
  - створює авторизований користувач (`applicantId == uid`, `status == PENDING`, оголошення існує, `OPEN`, і `ownerId` збігається з власником оголошення та не дорівнює `uid`);
  - автор може змінити лише `status` з `PENDING` на `CANCELLED`;
  - власник може встановлювати `APPROVED`, `REJECTED`, `REVOKED`;
  - видаляє лише власник оголошення.
- `favorites`:
  - читає, створює (з перевіркою `id == userId_listingId`) і видаляє власний запис користувач;
  - видаляти вподобання на оголошення може також його власник.

Реалізується на етапі 13 і перевіряється вручну.

## 5. Власні структури даних (`src/core/data-structures`)

### 5.1. `HashTable<K, V>`

- Масив кошиків-ланцюжків. Ключ перетворюється на рядок.
- Хеш-функція FNV-1a (32 біти). Початкова ємність 16, подвоєння при навантаженні понад 0,75 з перехешуванням.
- API: `set`, `get`, `has`, `delete`, `size`, `keys()`, `values()`, `entries()`, `clear()`.

### 5.2. `HashSet<T>`

- Побудований поверх `HashTable<T, true>`.
- API: `add`, `has`, `delete`, `size`, `values()`, `clear()`.
- Статична `intersect(a, b)` обходить меншу множину.

### 5.3. `BTree<K, V>` (`BTreeNode<K, V>`)

- Конструктор приймає порівняльник і мінімальний степінь `t` (за замовчуванням 4).
- API: `insert` (існуючий ключ – оновлення значення), `delete`, `get`, `has`, `size`, `clear()`.
- Генератори: `entries()` (зростання), `entriesDescending()` (спадання), `rangeScan(from, to)` (обидві межі включно).
- Видалення за схемою з позичанням у сусіда й злиттям вузлів.
- Складені ключі: `[число, id]`, порівняння спочатку за числом, потім за id (`compareSortKeys`).

### 5.4. `Trie` (`TrieNode`)

- Вузол: нащадки (`HashTable<string, TrieNode>`), множина id оголошень (`HashSet`), `label` – вихідний текст сегмента адреси (для гарних підказок).
- API:
  - `insert(path, id, segments)` – додає id у кінцевий вузол і зберігає `label` для кожного рівня;
  - `remove(path, id)` – видаляє id та прибирає порожні гілки;
  - `findByPrefix(prefix)` – збирає id піддерева (ітеративний обхід);
  - `suggest(prefix, limit)` – повертає унікальні наступні сегменти (за `label`) для автодоповнення.

### 5.5. Допоміжні функції (`src/core/utils`)

- `addToBucket(table, key, id)`, `removeFromBucket(table, key, id)` – робота з `HashTable<K, HashSet<string>>`, порожні кошики видаляються.
- `compareSortKeys`.

## 6. Репозиторії

Кожен репозиторій володіє структурами напряму. Спільного базового класу немає. У кожному:

- `upsert(item)`: беремо старий запис з первинного B-дерева, якщо він є – видаляємо його зі **всіх** індексів за старими значеннями, потім додаємо новий у первинне B-дерево та індекси.
- `upsertMany(items)`, `remove(id)`, `get(id)`, `clear()`.

Усі індекси мають окремі приватні методи `addToIndexes(x)` і `removeFromIndexes(x)`.

### 6.1. `ListingRepository`

| Структура | Ключ → значення | Призначення |
|---|---|---|
| `BTree` byId | `id` → `Listing` | первинне сховище |
| `BTree` byCreatedAt | `[createdAt, id]` → id | сортування за датою |
| `BTree` byArea | `[area, id]` → id | сортування за площею |
| `BTree` byPrice | `[price, id]` → id | сортування за ціною, діапазон ціни |
| `HashTable` byRooms | `rooms` → `HashSet<id>` | фільтр за кімнатами |
| `HashTable` byOwner | `ownerId` → `HashSet<id>` | фільтр за власником |
| `Trie` byAddress | `address.toTriePath()` → id | пошук за адресою, підказки |

Метод `search(query: ListingQuery): Listing[]`:

1. `candidates = null` (означає «усі»).
2. Адреса: `Trie.findByPrefix` – множина id, перетин з `candidates`.
3. Кімнати: точне значення – один кошик; «4+» – об'єднання кошиків з ключами ≥ 4. Перетин.
4. Власник: кошик `byOwner`. Перетин.
5. Діапазон ціни: `byPrice.rangeScan([min, ''], [max, '￿'])` – множина id. Перетин.
6. Сортування: обхід B-дерева за полем і напрямом (`entries` / `entriesDescending`), залишаємо id з `candidates` (або всі, якщо `candidates` порожній) і беремо `Listing` з `byId`.

Також `suggestAddress(parts)` – підказки для автодоповнення на основі `Trie.suggest`.

### 6.2. `ApplicationRepository`

| Структура | Ключ → значення | Призначення |
|---|---|---|
| `BTree` byId | `id` → `Application` | первинне сховище |
| `HashTable` byListing | `listingId` → `HashSet<id>` | заявки на оголошення |
| `HashTable` byApplicantStatus | `${applicantId}:${status}` → `HashSet<id>` | заявки орендаря за станами |

Методи: `findByListing(listingId, status?)`, `findByApplicant(applicantId, status?)`, `countByApplicantStatus`, `countPendingByListing`. Результати впорядковуються за датою (нові спершу) вбудованим `sort` – обсяги малі.

### 6.3. `FavoriteRepository`

| Структура | Ключ → значення | Призначення |
|---|---|---|
| `BTree` byId | `id` → `Favorite` | первинне сховище |
| `HashTable` byUser | `userId` → `HashSet<listingId>` | збережені, перевірка «вподобано» |

Методи: `findListingIds(userId)` (за датою додавання), `isFavorite(userId, listingId)`.

### 6.4. `ListingQuery`

Імутабельний опис запиту з fluent-інтерфейсом:

- `address(parts: { country?, city?, street?, building? })`
- `rooms(value, orMore)`
- `priceBetween(min?, max?)`
- `ownedBy(uid)`
- `sortBy(field: 'createdAt' | 'area' | 'price', direction: 'asc' | 'desc')`

Значення за замовчуванням: сортування за датою створення за спаданням.

**Префікс адреси:** заповнені сегменти нормалізуються й з'єднуються роздільником. Усі сегменти, крім останнього заповненого, є повними (за ними йде роздільник), останній – префіксом. Сегмент можна задати лише після всіх попередніх.

## 7. Синхронізація (`FirestoreSyncService`)

- Залежності: Firestore, три репозиторії.
- `startPublic()`: викликається один раз при старті застосунку, до входу. Відкриває слухач `onSnapshot` для `listings` (усі оголошення).
- `startUser(uid)`: викликається після входу. Відкриває 3 слухачі `onSnapshot`:
  - `applications` за `ownerId == uid`;
  - `applications` за `applicantId == uid`;
  - `favorites` за `userId == uid`.
- Кожен снепшот обробляється пакетом: події `added` / `modified` – `upsert`, `removed` – `remove`, потім **один** виклик `notify()`. Конвертація документів – функціями-конвертерами.
- Готовність має два прапорці: `listingsReady` (перший снепшот `listings`) і `userDataReady` (перші снепшоти трьох користувацьких слухачів; для гостя одразу `true`). До готовності UI показує skeleton.
- Observer: `subscribe(listener)` → функція відписки, `getVersion()` – лічильник, що збільшується при кожному `notify()`. Repositories про підписників не знають.
- `stopUser()`: при виході відписує три користувацькі слухачі, очищає `ApplicationRepository` і `FavoriteRepository`, скидає `userDataReady`. Оголошення залишаються, каталог далі працює як для гостя.
- `stop()`: відписує всі слухачі й очищає всі репозиторії (при закритті застосунку).
- Помилки слухачів (наприклад, `permission-denied`) переводять сервіс у стан `error` з повідомленням для UI.

## 8. Сервіси

Сервіси читають репозиторії для перевірок, пишуть тільки у Firestore і не змінюють індекси напряму.

- **AuthService**: `register`, `login`, `logout`, `onAuthChange(cb)`, `getProfile(uid)`. Перетворення логіна на email і переклад помилок.
- **ListingService**: `create`, `update`, `cancel`, `reopen`.
  - `cancel`: batch з видаленням оголошення, його заявок (з `ApplicationRepository.byListing`) і вподобань (разовий `getDocs(where listingId == id)`).
  - `reopen`: транзакція – оголошення в `OPEN`, схвалена заявка в `REVOKED`.
- **ApplicationService**: `submit`, `withdraw`, `reject`, `approve`.
  - `approve`: транзакція – оголошення в `CLOSED` з `approvedApplicationId`, заявка в `APPROVED`, решта `PENDING` у `REJECTED`.
  - Перевірка прав і станів через методи сутностей.
- **FavoriteService**: `add`, `remove`, `toggle`.

Валідація полів виконується лише на рівні форм: Zod-схеми в `src/lib/validation.ts` (вхід, реєстрація, оголошення, заявка) підключаються до `react-hook-form`, помилки показуються під відповідними полями. Сутності й сервіси значення полів не перевіряють, а контролюють лише стани, права та бізнес-правила (наприклад, подати заявку на власне оголошення не можна).

## 9. Збірка та інтеграція з React

- **ServiceContainer** (composition root): створює репозиторії, `FirestoreSyncService`, сервіси, один раз. Передається через `ServicesProvider` (React Context).
- **ServicesProvider**: при монтуванні викликає `sync.startPublic()`, тому оголошення завантажуються для всіх, включно з гостями.
- **AuthProvider**: підписується на `AuthService.onAuthChange`; після входу завантажує профіль і викликає `sync.startUser(uid)`, після виходу – `sync.stopUser()`.
- **DataGate**: у публічних сторінках чекає `listingsReady`, у захищених – `listingsReady` і `userDataReady`; при `error` показує повідомлення.
- **Гвард**: захищені сторінки неавторизованого користувача переспрямовують на `/login?next=<шлях>`; після входу відбувається повернення на `next`.
- Хуки використовують `useSyncExternalStore(sync.subscribe, sync.getVersion)` і обчислюють результати через `useMemo` за версією та параметрами:
  - `useListingSearch(query)`, `useListing(id)`, `useMyListings()`;
  - `useListingApplications(listingId, status?)`, `useMyApplications(status?)`;
  - `useFavoriteListings()`, `useIsFavorite(listingId)`;
  - `useAuth()`, `useServices()`.
- Усі сторінки з даними – клієнтські компоненти. Для гостя `useIsFavorite` повертає `false`, а списки заявок і вподобань порожні. Захист маршрутів – на клієнті (гвард у лейауті групи `(protected)`).

## 10. Інтерфейс

Стиль: мінімалістичний, світла тема, одна акцентна колір. Компоненти shadcn/ui: button, input, label, textarea, select, card, badge, tabs, dialog, alert-dialog, table, skeleton, dropdown-menu, popover, command, form, separator, sonner (сповіщення). Ціни форматуються `Intl.NumberFormat('uk-UA')`, дати – `Intl.DateTimeFormat('uk-UA')`.

### 10.1. Маршрути

| Маршрут | Призначення | Доступ |
|---|---|---|
| `/login`, `/register` | група `(auth)` | гості (авторизованих переспрямовує на `/`) |
| `/` | каталог | усі, група `(public)` |
| `/listings/[id]` | сторінка оголошення | усі, група `(public)` |
| `/favorites` | збережені | лише авторизовані, група `(protected)` |
| `/my/applications` | мої заявки | лише авторизовані |
| `/my/listings` | мої оголошення | лише авторизовані |
| `/my/listings/new` | створення | лише авторизовані |
| `/my/listings/[id]/edit` | редагування | лише власник |
| `/my/listings/[id]/applications` | заявки на оголошення | лише власник |

### 10.2. Навігація

```
RentUA   Оголошення  Збережені  Мої заявки  Мої оголошення            [Ім'я Прізвище ▾ → Вийти]
RentUA   Оголошення                                                   [Увійти]  [Зареєструватися]   (гість)
```

### 10.3. Каталог `/`

```
┌──────────────────────────────────────────────────────────────────┐
│ Країна [Україна ▾]  Місто [Запоріж…▾]  Вулиця [Поляк…▾]  Буд. [21]│
│ Кімнати: (Усі)(1)(2)(3)(4+)   Ціна: [від ___] – [до ___] грн/міс │
│ Сортувати: [Дата створення ▾] [↓]                    [Скинути]   │
├──────────────────────────────────────────────────────────────────┤
│ Знайдено 42 оголошення                                           │
│ ┌──────────────────────┐ ┌──────────────────────┐                │
│ │ Україна, місто       │ │ ...                  │                │
│ │ Запоріжжя, вулиця    │ │                      │            ♡   │
│ │ Полякова, буд. 21,   │ │                      │                │
│ │ кв. 71               │ │                      │                │
│ │ 2 кімн · 54 м²       │ │                      │                │
│ │ 8 500 грн/міс [Здається]│                      │                │
│ └──────────────────────┘ └──────────────────────┘                │
│                      [ Показати ще ]                             │
└──────────────────────────────────────────────────────────────────┘
```

- Поля адреси каскадні: місто активне після країни, вулиця після міста, будинок після вулиці. Підказки дає `suggestAddress` (Trie).
- Країна за замовчуванням «Україна».
- Фільтр кімнат – групові кнопки. Діапазон ціни – два числові поля.
- Параметри запиту зберігаються в URL (`?city=...&rooms=...`), щоб сторінка відновлювалась після навігації.
- Результати показуються порціями по 12 карток.
- Сердечко додає або прибирає оголошення з вподобаних. Гість при натисканні переспрямовується на вхід.

### 10.4. Сторінка оголошення `/listings/[id]`

```
┌──────────────────────────────────────────────────────────────────┐
│ ← Назад                                                          │
│ Україна, місто Запоріжжя, вулиця Полякова, буд. 21, кв. 71       │
│ [Здається]                                                    ♡  │
│ 2 кімнати · 54 м² · 8 500 грн/міс · Додано 12.10.2026            │
│ Опис: ...                                                        │
│ Власник: Олена Коваль · +380 50 123 45 67                        │
│                                  [ Подати заявку ]               │
└──────────────────────────────────────────────────────────────────┘
```

- Гість замість кнопки «Подати заявку» бачить «Увійдіть, щоб подати заявку» з переходом на вхід.
- Для власника замість кнопки «Подати заявку» показуються «Редагувати», «Заявки», «Закрити/Поновити», «Скасувати оголошення».
- «Подати заявку» відкриває діалог: ім'я (з профілю), контакт, коментар. Для закритого оголошення кнопка неактивна, якщо у користувача вже є заявка в очікуванні – підказка «Заявку вже подано».

### 10.5. Мої оголошення `/my/listings`

```
┌──────────────────────────────────────────────────────────────────┐
│ Мої оголошення                              [ + Створити ]       │
│ Сортувати: [Дата створення ▾] [↓]                                │
│ ┌────────────────────────────────────────────────────────────┐   │
│ │ м. Запоріжжя, вул. Полякова, 21/71      8 500  [Здається]  │   │
│ │ Заявок: 3 (2 нових)  [Заявки] [Редагувати] [Скасувати]     │   │
│ ├────────────────────────────────────────────────────────────┤   │
│ │ м. Київ, вул. Хрещатик, 10/5           12 000  [Закрито]   │   │
│ │ Заявок: 5            [Заявки] [Поновити] [Скасувати]       │   │
│ └────────────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────────┘
```

Список формується запитом `ownedBy(uid)` з тим самим сортуванням, що й у каталозі. «Скасувати» вимагає підтвердження в `AlertDialog`.

### 10.6. Форма оголошення (створення й редагування)

Поля: країна, місто, вулиця, будинок, квартира, кількість кімнат, площа, ціна, опис, ім'я власника, телефон (`+380XXXXXXXXX`). Під полями адреси – попередній перегляд `Address.format()`. Редагування доступне лише для оголошень у стані «Здається».

### 10.7. Заявки на оголошення `/my/listings/[id]/applications`

```
┌──────────────────────────────────────────────────────────────────┐
│ Заявки: Україна, місто Запоріжжя, вулиця Полякова, буд. 21, кв. 71│
│ Стан: (Усі)(Очікують)(Схвалені)(Відхилені)(Скасовані)(Анульовані)│
│ ┌──────────────────────────────────────────────────────────────┐ │
│ │ Ім'я     │ Контакти    │ Коментар   │ Дата  │ Стан  │ Дії   │ │
│ │ Іван П.  │ +380...     │ З собакою  │ 12.10 │ Очікує│ [✔][✖]│ │
│ └──────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```

«✔» відкриває підтвердження: «Схвалити заявку й закрити оголошення? Решту заявок буде відхилено».

### 10.8. Мої заявки `/my/applications`

Вкладки станів із лічильниками: Усі, Очікують, Схвалені, Відхилені, Скасовані, Анульовані. Рядок заявки: адреса (посилання на оголошення), ціна, дата, стан. Для «Очікує» – кнопка «Скасувати».

### 10.9. Збережені `/favorites`

Сітка карток, як у каталозі, лише вподобані оголошення, найновіші додавання першими.

### 10.10. Вхід і реєстрація

Центрована картка. Вхід: логін, пароль. Реєстрація: логін, ім'я, прізвище, пароль, підтвердження пароля. Помилки валідації – під полями.

## 12. Класи та їхні ролі

| Клас | Відповідальність |
|---|---|
| `BTreeNode`, `BTree` | вузол і B-дерево: вставка, видалення, пошук, діапазон, впорядкований обхід |
| `TrieNode`, `Trie` | префіксне дерево: вставка, видалення, пошук за префіксом, підказки |
| `HashTable`, `HashSet` | хеш-таблиця з ланцюжками й множина на її основі |
| `Address` | складові адреси, `format()`, `toTriePath()` |
| `Listing`, `Application`, `Favorite`, `UserProfile` | сутності, перевірка інваріантів, переходи станів |
| `ListingRepository`, `ApplicationRepository`, `FavoriteRepository` | зберігання сутностей та їхні індекси, запити |
| `ListingQuery` | опис запиту каталогу |
| `FirestoreSyncService` | слухачі Firestore, оновлення репозиторіїв, готовність, сповіщення UI |
| `AuthService`, `ListingService`, `ApplicationService`, `FavoriteService` | бізнес-операції та перевірка прав, запис у Firestore |
| `ServiceContainer` | створення й зв'язування об'єктів |

Усього 21 клас, жодного `extends`.

## 13. Етапи реалізації

Кожен етап завершується компіляцією без помилок (`tsc`, `next build`) і ручною перевіркою описаного результату.

1. **Каркас.**
   - Створити Next.js (TypeScript, App Router, Tailwind) у `code/`, підключити shadcn/ui і потрібні компоненти.
   - Налаштувати `strict`, `.env.local.example`, `src/lib/firebase.ts`.
   - Результат: порожній застосунок запускається.
2. **Хеш-структури.** `HashTable`, `HashSet`, допоміжні функції.
3. **B-дерево.** `BTree` з вставкою, видаленням, діапазоном і обходами в обох напрямках.
4. **Trie.** `Trie` із підказками.
   - Етапи 2–4 перевіряються тимчасовим скриптом `scripts/try-structures.ts` (запуск через `tsx`), який виводить результати в консоль. Після перевірки скрипт видаляється.
5. **Домен.** `Address`, сутності, `DomainError`, переходи станів.
6. **Репозиторії та запит.** `ListingRepository` (індекси, `search`, `suggestAddress`), `ApplicationRepository`, `FavoriteRepository`, `ListingQuery`.
7. **Синхронізація.** Конвертери, `FirestoreSyncService`, `ServiceContainer`.
8. **Автентифікація.** `AuthService`, `AuthProvider`, сторінки входу й реєстрації, гвард маршрутів, `DataGate`.
9. **Сервіси.** `ListingService`, `ApplicationService`, `FavoriteService`.
10. **Каталог.** Хуки, картки, форма пошуку з каскадними підказками, фільтри, сортування, вподобання, пагінація, стан у URL.
11. **Сторінка оголошення.** Деталі, діалог заявки, кнопки власника.
12. **Сторінки орендодавця.** Мої оголошення, форма створення й редагування, заявки на оголошення.
13. **Сторінки орендаря.** Мої заявки за станами, збережені.
14. **Правила й дані.** `firestore.rules`, `scripts/seed.ts` (30–50 оголошень у 10–12 містах України, кілька демо-акаунтів, приклади заявок і вподобань).
15. **Завершення.** Огляд інтерфейсу на вузьких екранах, обробка помилок і порожніх станів, README із запуском.

## 14. Ручна перевірка

- Реєстрація: різні паролі, зайнятий логін, коректна реєстрація, поява профілю в `users`.
- Вхід і вихід, гвард маршрутів, відновлення сесії після перезавантаження.
- Гість без входу: каталог, пошук, фільтри, сортування й сторінка оголошення працюють; вподобання, заявка й захищені сторінки переспрямовують на вхід і після входу повертають назад.
- Вихід із акаунта: каталог залишається доступним, заявки й вподобання зникають з пам'яті.
- Створення оголошення: у другому вікні браузера з іншим акаунтом воно з'являється без перезавантаження.
- Редагування адреси й ціни: оголошення знаходиться за новою адресою й зникає зі старої, порядок сортування за ціною оновлюється.
- Пошук: країна, країна + місто (повне й часткове), + вулиця, + будинок; підказки на кожному рівні; регістр не впливає.
- Фільтри: кімнати 1, 2, 3, 4+; діапазон ціни (обидві межі, лише одна); комбінація пошуку, кімнат і ціни.
- Сортування за датою, площею й ціною в обидва боки поверх фільтрів.
- Заявки: подання, повторне подання при наявній заявці, власник не може подати, скасування, відхилення.
- Схвалення: оголошення закривається, інші заявки відхиляються, орендарі бачать зміни в реальному часі.
- Поновлення: оголошення знову «Здається», схвалена заявка «Анульована».
- Скасування оголошення: зникають з каталогу, заявок, збережених у всіх користувачів.
- Вподобання: додавання, видалення, відображення на сторінці збережених.
- Правила Firestore: спроби змінити чуже оголошення чи заявку відхиляються, помилка відображається користувачу. Неавторизований клієнт читає `listings`, але не може читати `applications`, `favorites`, `users` і писати будь-що.
